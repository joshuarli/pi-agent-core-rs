# V0 completion audit

This is the pre-completion evidence checklist for the active V0 goal. It is intentionally stricter
than a green crate test: every `plan.md` definition-of-done item needs an implementation boundary,
deterministic proof, and a final quality check before V0 may be declared complete.

| Requirement | Current evidence | Required before V0 completion |
| --- | --- | --- |
| No Pi installation/CLI at runtime | Rust runner calls the library; upstream runner imports pinned sources in-process; the live controller rejects host Pi executables. | Preserve this boundary in every future runner and evaluation controller. |
| No ambient runtime discovery/session/UI | Core builder takes provider/tools/hooks explicitly; explicit-workspace profile tests prove isolated workspaces and an empty default shell environment; scope excludes sessions and TUI. | Preserve the explicit-workspace and empty-environment tests. |
| Pinned SDK behavioral parity | Thirty checked-in declarative fixtures compare pinned upstream, Rust, and goldens, including deterministic stream/tool cancellation, async before-hook cancellation, active-run steering/follow-up arrival, awaited terminal observer settlement, context conversion and next-turn model/thinking replacement, unknown-tool/schema-validation recovery, before/after-hook termination, turn-stop policy, length, provider error/abort, mixed execution, and all-tools termination. | Keep every supported ledger row tied to its fixture; add a fixture before expanding the supported subset. |
| Tool scheduling/hooks/queues | Success/error, parallel completion, updates, before/after hooks, context conversion/next-turn replacement, async before-hook cancellation, queue modes including active-run steering/follow-up arrival, awaited terminal observer settlement, assistant-tail continuation, mixed sequential/parallel execution, and all-tools termination are covered. | Retain the full corpus gate; expand only for a newly supported hook/queue/observer contract. |
| Default profile | Captured exact prompt, active order, standard definitions, schemas, snippets, and guidelines. Direct pinned source checks run success/invalid/host-error cases through virtual adapters for `read`, `bash`, `edit`, `write`, `find`, and `ls`; a separate process-seam check runs `grep` with `PI_CODING_AGENT_DIR` forced empty before source import and requires PATH `rg`, never `~/.pi`. Rust exercises the matching explicit capability boundary for all seven. | Retain both source and Rust profile gates. Local search remains replaceable rather than emulating Pi's managed-ripgrep discovery. |
| Structured cancellation/reuse | Core tests and declarative fixtures cover model-stream, tool-update, async tool-preparation, explicit abort, drop, terminal settlement, and reuse paths; `incremental_model_stream` proves a delta is observable before a live source settles and that the executor-neutral cancellation future wakes its waiter. | Add a deterministic checkpoint fixture before changing a cancellation boundary or queue policy. |
| Trace behavior | Optional `TraceObserver`, JSONL and CBOR sinks, sink-failure isolation, and no-trace/JSONL/CBOR agent-behavior identity test. | Retain the identity test in the final workspace suite. |
| Dependency/runtime boundary | Pinned-nightly checks, Miniserde protocol boundary, Smol-only runner, and final lockfile/tree/source audit: no Tokio, `pi-ai`, or unsafe Rust constructs. | Re-run the same audits after dependency or runtime changes. |
| Hardening | Focused unit/parity suite plus deterministic completion-order, terminal-cleanup/reuse, lifecycle-balance, and profile-composition matrices; 1,000 isolated agents, bounded non-blocking subscription overflow, two-workspace default-profile isolation, and concurrent run-claim race tests. | Extend the deterministic matrices when a new state transition or profile composition is introduced. |
| Comparative coding evaluation | Checked-in `baselines.deepseek-v0.json` invokes explicit upstream/Rust adapters through `vault OPENROUTER_API_KEY -- bash …`, never a host Pi CLI. The upstream adapter imports pinned source tools/prompt/Agent directly; the Rust eval-only binary drives `PiDefaultCodingProfile` on pinned nightly + Smol while the library remains transport-free. Its light final gate has one paired `READY` control and one hidden-oracle task that asks for a single standard-library `intervals.py` write, with one-at-a-time waves to avoid attributing provider saturation to either runtime. On 2026-08-14, `python3 evals/controller.py run --baselines evals/baselines.deepseek-v0.json --allow-provider --out evals/results/deepseek-v0-light-1024.json` scored 2/2 for both baselines: both coding tasks passed with one `write` call and both `READY` controls passed; no attempt timed out. The local report is intentionally ignored because it is provider-specific. | Re-run the explicit manifest when the pinned source, profile, task contract, model/provider revision, or adapter changes; retain the command and redacted summary as release evidence |

The table is not a status claim. A row counts as complete only when its final evidence is present in
the worktree and passes the verification command that covers the stated scope.
