# V1 — Optional Luau policy plane

V1 adds programmable policy to the completed V0 Rust runtime. Its guiding rule is:

> Rust owns mechanism. Luau owns policy. The world runtime supplies capabilities.

This is an embedded extension language, not another agent implementation or a general-purpose
application runtime. It removes the former Node/napi/TypeScript direction entirely. Potential
IPC, C ABI, WASM/component, Python, or other external interfaces remain future work only when a
concrete use case justifies them.

## 1. Layering and ownership

`pi-agent-luau` now uses `mlua`'s pinned `luau-jit` backend with `send`; its first shipped slice
loads a hermetic declarative policy and invokes an optional synchronous `before_tool_call` hook.
It depends on `pi-agent-core`; the core never depends on `mlua`, Luau, scripting types, world
APIs, or a policy bundle. A pure Rust worker therefore has zero VM construction, memory, and
scheduling cost. [`docs/luau-extensions.md`](docs/luau-extensions.md) documents the supported
extension contract.

Rust remains authoritative for agent state transitions, message history, streaming, tool-call
sequencing and parallel ordering, queues, cancellation, settlement, tracing, usage, failure
classification, and resource ownership. Luau can request policy decisions—permit or transform a
tool call, define a lightweight tool, stop after a turn, react to an event, annotate a trace, or
express orchestration intent—but every action crosses a Rust validation boundary.

The caller-owned Smol executor remains the sole scheduler. `mlua` async coroutines may later yield
while a Rust future is pending and resume when the host polls it; they are not part of the current
extension ABI. Luau never owns an event loop, thread scheduler, tool scheduler, or agent
scheduler. Tokio is prohibited as a direct dependency or enabled feature here as in every other
workspace crate.

## 2. Hermetic capability ABI

Expose a small, stable scripting ABI through host-controlled modules, initially `@agent`,
`@world`, `@trace`, `@task`, `@json`, and `@time`. Scripts see simple tables, functions, and
discriminated values—not mechanically exported Rust structs or the internal object graph.

Every VM receives an explicit, serializable capability manifest, for example:

```json
{
  "agent": ["events", "tools", "stop"],
  "world": ["fs.read", "fs.write", "exec"],
  "trace": ["emit"]
}
```

There is no ambient filesystem, process, environment, network, home directory, host cwd, clock,
native FFI, dynamic library, package registry, or OS-command authority. The rich object is the
injected world capability, not the scripting environment. Different workers may receive only the
authority their role needs.

Module resolution is host-controlled and closed: virtual capability modules and optional
bundle-local relative modules are allowed. Absolute imports, implicit cwd/HOME searches,
LuaRocks/npm-like resolution, global package paths, native plugin loading, and runtime network
fetches are rejected. A policy bundle has a deterministic dependency graph and hash.

## 3. VM construction, typing, and limits

Every VM starts from a documented minimal Luau environment: table, string, UTF-8, math, and
coroutine helpers; read-only sandboxed globals; no I/O, OS, package/module loader, debug API, or
host bindings; and applied limits. JIT is enabled before a policy is loaded. It inherits no host
globals or mutable process state. Generate or maintain Luau declarations for every future host
module and run the Luau type checker independently in examples and CI so generated policies
receive precise diagnostics before execution.

The host enforces practical instruction, memory, recursion, coroutine, host-call, and wall-time
budgets. Exact enforcement may follow `mlua`/Luau capability, but a runaway loop, recursion,
allocation, or coroutine explosion must not monopolize a worker. Destruction of a VM cancels and
settles its pending host operations.

## 4. Async, cancellation, and errors

`mlua` async host functions bridge Rust futures to Luau coroutines. A policy may write
`world.exec({...})` in a synchronous-looking style; its coroutine yields until the explicit world
capability future resolves. Cancellation originates in Rust and propagates through pending model,
tool, world, task, nested-policy, and hook work. It must leave neither orphaned futures nor
stranded coroutines, emit no post-settlement events, and leave the surrounding agent reusable.

Translate Luau syntax, typecheck, runtime, host-capability, cancellation, resource-limit, and
forbidden-module failures into typed errors. Hook policy defines whether a failure aborts a run,
blocks a tool, returns a structured result, or is ignored; it never corrupts Rust state.

## 5. Hooks, tools, and orchestration

Adapt the completed Rust hook contracts to a clean Luau surface such as `before_tool_call`,
`after_tool_call`, `before_turn`, and `after_turn`. The script API need not mirror awkward Pi
names, but its adapter must preserve the Rust parity semantics.

Luau may register a tool with a JSON Schema and a coroutine-backed handler. The adapter registers
an ordinary Rust `AgentTool`; the Rust scheduler still validates, prepares, executes, emits
updates, settles, and inserts results. Fundamental operations—world forking, process execution,
filesystem/storage, networking, sandbox control, snapshot/restore—remain Rust or external-world
mechanisms. Luau composes them through granted capabilities.

Design the ABI so a later `agent.spawn` or `world.fork` can express composition intent, but do not
build a swarm framework in V1. Scheduling, child lifecycle, and world ownership remain Rust host
responsibilities.

## 6. Tracing, isolation, and measurement

The canonical trajectory stays in `pi-agent-trace`; VM internals are never trajectory state. A
script may add structured trace annotations, but those annotations cannot alter replay semantics.

Test separately from core parity: basic loading and module denial; typecheck and runtime errors;
hook/tool adaptation; sequential and nested async yields; cancellation at every yield boundary;
two-agent global/capability isolation; resource abuse; recovery after a script failure; and 100 to
1,000 Luau-backed worker stress. Core parity remains testable with no VM and never uses Luau as
its oracle.

Benchmark the incremental policy cost against pure Rust: VM startup/teardown and idle memory,
bundle loading, hook latency, Rust-to-Luau and capability-call overhead, table conversion, and
async yield/resume. Explore one VM per agent, process, or isolated environment only after
measuring semantic-isolation and density tradeoffs; do not share mutable VM state by default.

## 7. Examples and exit criteria

Provide Rust examples plus Luau bundles for a basic policy, custom tool, hooks, orchestrator
intent, and swarm policy. A small `pi-agent` launcher may run a policy bundle for development and
debugging only; it is not a TUI or session application.

V1 is complete when a pure Rust agent still runs without a VM; Luau policies are hermetic and
capability-scoped; coroutine/future/cancellation behavior is leak-free; Luau tools use the normal
Rust scheduler; limits contain adversarial scripts; typechecking and integration suites pass; and
benchmarks quantify the optional policy overhead. The design must leave room for a future WASM
extension plane without making it a current dependency.
